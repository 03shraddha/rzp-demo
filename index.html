what it does
search_razorpay_docs(query, product?, limit?)
BM25 full-text search across 2,200+ razorpay docs. returns ranked results with url, title, heading path, snippet, and relevance score.
filters by product: payments | api | x | partners | payroll | pos | webhooks | errors
get_razorpay_docs(urls[])
fetches the complete markdown content of up to 20 docs by canonical razorpay.com/docs/... url.
full doc, not a snippet. gives the agent complete context before it writes the api call
2,200+ docs 20,000+ chunks sub-100ms lookup zero ongoing cost works offline
why this exists
01: knowledge cutoff
llms have a training cutoff. razorpay ships every week.
  • training data is 12 to 24 months old. razorpay ships every week
  • deprecated auth flows still live in the model's memory
  • wrong field names get written with the same confidence as correct ones. no warning
02: web search is not enough
agents can do web search. that's not good enough.
google agrees, they built the google developer docs mcp for the same reason
  • the agent only searches when it thinks it might be wrong. it usually doesn't
  • results mix blog posts, old stack overflow answers, and competitor tutorials
  • the same webhook query returns 4 different code patterns. the model picks one
03: but razorpay already has an mcp
both mcps are built for different moments in the workflow.

faq
what if the docs go stale?
there's a built-in python refresh command. run it before a big integration or schedule it to auto-refresh. it re-fetches from razorpay's github in under 5 minutes.
will the agent use this automatically?
once installed, the tool is always available. instruct the agent once: "for any razorpay integration question, use the docs mcp." it handles the rest.
who benefits from this?
  • bookmyshow adding upi checkout
  • swiggy handling refunds on failed orders
  • groww wiring webhooks for transaction status
  • zepto reconciling cod payouts at scale
why not let razorpay's own mcp do this too?
  • the action mcp says "i will do x for you" while the docs mcp says "here is what you need to know to do x yourself" and mixing them risks the agent calling actions when it should be reading first
  • run them as separate servers and let developers install whichever they need, different workloads need different mental models
